# 观古定名 · 以《左传》五类命名原则为主线

把《观古定名知识库》Excel 变成**可运行、可解释、可追溯**的取名程序。
命名依据取自《左传·桓公六年》：**"名有五：有信，有义，有象，有假，有类。"**

**默认不与算卦、起卦、卦象推导关联；不作命运、财富、疾病等吉凶预测。**

---

**在线版：<https://lpllpl97.github.io/guangudingming/>**

## 快速开始（本机运行）

```bash
cd <本目录>
python mobile/server.py 6700
# 浏览器打开 http://127.0.0.1:6700/
```

零依赖：只用 Python 标准库（`sqlite3` / `http.server` / `urllib`），不需要 `pip install` 任何东西，也不需要 Node/构建工具。

命令行直接用引擎：

```bash
python engine/engine.py --surname 林 --text "希望孩子聪慧好学、性格温润，有远大志向" --top 3
python engine/engine.py --surname 欧阳 --generation 明 --top 3        # 类：字辈
python engine/engine.py --surname 林 --fixed 知 --principles F02 --top 3
python engine/engine.py --help
```

## 它和"让大模型编名字"有什么不同

| | 大模型编名字 | 本程序 |
|---|---|---|
| 依据 | 模型隐式记忆，可能编造出处 | 《左传》五类原则 + 可核验原文库 |
| 出处 | 常出现"看起来像但不存在"的引文 | 引文只在原文库确有该条时才标注"原文可核"，否则明确写"文化约定" |
| 结果 | 每次不同、不可复现 | 同输入同输出（可指定 `--seed`），可审计 |
| 速度 | 数秒、有 token 成本 | 100ms 内、零成本 |
| 可维护 | 改行为要重训/改提示词 | 改 Excel/JSON 后重建数据库即可 |

**核心机制**：知识库的每个字都带"五类原则归属 + 归属依据 + 出处"。生成的名字必须能说清"用了哪一类原则、依据是什么、出自哪一句"，说不清的不进候选。

## 五类命名原则怎么落到程序里

**界面上可以多选**。选中哪一类，下面就展开该类专属的填写面板——不同类别问的东西不一样。

| 原则 | 一句话理解 | 选中后要填什么 | 引擎里的作用 | 可归属汉字 |
|---|---|---|---|---|
| **信** F01 | 用真实发生过的事做依据 | 出生时令 / 天气 / 时刻 / 纪念事件 | 识别为时令·天气·时辰·节庆（14 类），**字池收敛到能承载该事实的字**（"冬天+下雪"→雪霜梅霁素柏…），并计入 S09 | 5 + 事实词库 99 字 |
| **义** F02 | 用希望孩子成为什么样的人来取名 | 第三步勾选"表达目标" | 按品格语义选字 | 75 |
| **象** F03 | 用自然界的物象表达愿景 | 第三步勾选"文化意象" / 风格 | 按意象选字 | 101 |
| **假** F04 | 借**人造之物**的文化含义取名 | 想借的外物（玉器/佩饰/礼器/乐器/文房/舟楫/织绣） | 从**全字库**召回该物相关字，**每个候选都必须真的用上**，并计入 S10 | 7 个器物族 + 全库借物召回 |
| **类** F05 | 按家族传承、辈分取名 | 字辈 / 家族传承字 | **所有候选必须包含该字** | 13 |

每一类的说明文案来自数据库（`principle_guide` 表），不是写死在前端：
点卡片上的"展开说明"可以看到该类的原典表述、含义、问什么、怎么填、例子，以及该类可用的字。

## 评分维度

| ID | 维度 | 权重 | 说明 |
|---|---|---|---|
| S01 | 文化证据度 | 0.20 | 出处可追溯性 + 原文可核覆盖率 + 多源加成 |
| S02 | 需求匹配度 | 0.30 | 与用户需求标签的语义一致程度（**没勾选目标时该维度不计权**） |
| S03 | 音律可用性 | 0.17 | 声调起伏、声母相异、韵母不相撞、避免三连同调 |
| S04 | 字形可用性 | 0.10 | 笔画适中、结构不重复、无生僻叠加 |
| S05 | 现代适配度 | 0.13 | 人名常用度、谐音风险、风险词表 |
| S06 | 组合互补度 | 0.10 | 语义不重合、意象跨类、虚实结合、非同源堆叠 |
| S07 | 独特性 | 0.00 | 探索维度，默认不计权 |
| **S08** | **性别契合度** | **0.18** | 契合 1.00 / 中性 0.72 / 相反 0.35。仅在选了非中性时计入 |
| **S09** | **命名依据契合度（信）** | **0.20** | 事实直接对应字 1.00 / 典型物象 0.70 / 氛围类 0.40。仅在识别出事实时计入 |
| **S10** | **借物契合度（假）** | **0.30** | 直接用到该物 0.92~1.00 / 取该物文化含义 0.78 / 未命中 0。仅在指定外物时计入 |

**硬门槛**：谐音陷阱（如"失误""无能"）与风险词表命中 → 直接淘汰；两字均为高生僻度 → 直接淘汰。

**严格约束**（候选不足时宁可少给，也不混入无关组合）：
字辈字/保留字必须出现在每个候选里；「假」指定的外物必须落到字上；「信」识别出的事实在每个候选里都要有字承载；选了性别倾向则不允许出现相反倾向的字。

## 更新知识库

**改数据，不要改代码。改动后必须走完下面 5 步**（Excel 是导出产物，不要直接改 Excel）：

```bash
# 1) 改数据源
#    db/src/hanzi.json            加字 / 改语义 / 补出处
#    db/src/expand_batch*.json    分批扩充字库（新增字放这里，便于追溯）
#    db/src/principles.json       五类归属 + 原则用户说明 + 风险词表
#    db/src/fact_lexicon.json     出生事实 → 字
#    db/src/evidence_patch*.json  补可核验原文 / 修正出处

# 2) 重建数据库（先停服务，否则数据库被占用会报错）
python tools/build_db.py

# 3) 跑回归
node tools/test_api.js && node tools/test_web.js && node tools/test_single_char.js
python tools/test_integration.py
python tools/verify_citations.py     # 出处质检，应为 0 项待复核

# 4) 导出新版本数据库 Excel（同时写版本清单、SQLite 快照、报告版本记录）
python tools/export_excel.py --note-file 变更说明.txt

# 5) 重启服务
python mobile/server.py 6700
```

**版本留痕三处同步**：`knowledge base/` 里的 Excel「00_版本记录」、
`VERSION_MANIFEST.json`、`docs/01_数据库体检与优化报告.md` 的「版本记录」区。
详见 `knowledge base/README.md`。

重建后会自动校验：外键悬空、声调缺失、原则归属悬空等，结果写在 `db/build_report.txt`。

若要改评分权重或规则，改 `tools/build_db.py` 里的 `SCORE_DIMS` / `ENGINE_RULES`（权重之和必须为 1.0），并在 `engine/engine.py` 里实现对应判定。

## 已知限制（下一版要补的）

1. **字库规模**：757 字（原库 184 字）。五类归属：信 150 / 义 226 / 象 228 / 假 119 / 类 120。
   已用 384 个常用名用字做覆盖检查，仅剩「石」「女」「男」3 个不适合作名用字的未收录。
   《通用规范汉字表》一级字约 3500 个，目前仍是子集；但常用取名用字已基本覆盖。
2. **性别倾向已可用**：偏男性标注 134 字、偏女性 118 字。
   选性别倾向时会保证每个候选至少有一个字契合该倾向，且不出现相反倾向的字。
3. **《左传》六忌已接入**：不以国、不以官、不以山川、不以隐疾、不以畜牲、不以器币，
   命中给软提示（不否决），如「岍」「汧」「泠」「沅」「湘」会提示山川之忌。
   不过带明确性别色彩的常用字仍有不少没收录，可继续补。
4. **出处覆盖率**：326/757 字的引文可核验（原文库 402 条原文），其余标注为文化约定。
   新增字多数只到"典籍+篇名"这一级，未逐条绑定原句。要进一步提升，需要继续往
   `db/src/evidence_patch*.json` 里补可核验的原文（每条都标明典籍与篇名）。
5. **风险词表是种子级**：33 条。谐音陷阱与公众人物/品牌近似名需要持续补充。
6. **音律只按普通话**：未考虑方言读音与姓氏古音；声母/韵母规则是启发式的。
7. **「信」的事实识别依赖关键词**：目前覆盖时令/天气/时辰/节庆 14 类。
   写"腊月二十八"这类具体日期识别不到，写"冬天""下雪"这类才命中。
8. **T13 的 80 条历史组合实验未回填标签**（原库标签全部悬空），暂未用于回归测试。

## 边界声明

- 命名依据限于《左传·桓公六年》五类原则及其可解释的文化语义转化，**不启用算卦、起卦、卦象选字**。
- **不作**命运、财富、疾病等吉凶预测。
- 引文标注分两档：`原文可核`（原文库确有该条，附书名与篇名）与 `文化出处/文化约定`（有文献语境但未绑定单句原文）。**不把文化约定包装成原典引文。**
- 名字的最终选择权在用户；程序提供的是可解释的候选与依据。

## 数据是怎么更新的（维护者看）

`db/naming.db` 是**唯一输入**，网页数据不手工维护：

```
db/naming.db ──tools/export_frontend_data.py──▶ web/kbdata/kb.js
```

推送 `db/naming.db` 到 `main` 后，GitHub Actions 会自动重新导出并发布。为了避免"网页数据落后于知识库"，本地改完库后可以随时自查：

```bash
python tools/export_frontend_data.py --check      # 比对 kb.js 与库是否一致（不一致会报错）
python tools/export_frontend_data.py --verify     # 数据充分性：走一遍引文链
```
